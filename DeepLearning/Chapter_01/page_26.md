## 🧠 فصل ۲۱ 🚀 RAG پیشرفته در سطح صنعتی (Production-Level RAG)

در نسخه‌های قبلی دیدیم که RAG چگونه با ترکیب Embedding، Vector Database و LLM یک سیستم پاسخ‌گویی هوشمند ایجاد می‌کند. اما در دنیای واقعی، سیستم‌های RAG ساده‌ای که فقط “retrieve + generate” انجام دهند، معمولاً در محیط‌های صنعتی کافی نیستند.

مشکل اصلی اینجاست که داده‌ها واقعی، بزرگ، نامرتب و چندمنبعی هستند. همچنین کیفیت پاسخ فقط به «یافتن یک متن مرتبط» وابسته نیست، بلکه به انتخاب بهترین قطعه اطلاعات، رتبه‌بندی آن، و حتی نحوه ترکیب آن‌ها بستگی دارد. اینجاست که مفهوم **RAG پیشرفته (Advanced RAG)** وارد می‌شود.

## 🧠 مشکل RAG ساده چیست؟

در RAG ساده، معمولاً این اتفاق می‌افتد:

کاربر یک سؤال می‌پرسد → Embedding ساخته می‌شود → نزدیک‌ترین متن‌ها از Vector DB برمی‌گردند → به LLM داده می‌شود → پاسخ تولید می‌شود.

اما این روش چند مشکل مهم دارد:

گاهی اسناد بازیابی‌شده مرتبط هستند اما بهترین نیستند.
گاهی اطلاعات مهم در chunkهای دیگر پراکنده است.
گاهی متن بازیابی‌شده طولانی است و باعث سردرگمی مدل می‌شود.
گاهی شباهت برداری (Vector Similarity) کافی نیست.

پس نیاز به یک لایه هوشمندتر داریم.

---

## 🔍 مرحله ۱: Hybrid Search (ترکیب جستجوی معنایی و کلمه‌ای)

در RAG پیشرفته فقط به Embedding اکتفا نمی‌کنیم. ما دو نوع جستجو را ترکیب می‌کنیم:

* جستجوی معنایی (Semantic Search با Embedding)
* جستجوی کلیدواژه‌ای (Keyword Search مثل BM25)

ترکیب این دو باعث می‌شود هم مفهوم و هم کلمات دقیق پوشش داده شوند.

## 🧠 چرا Hybrid Search مهم است؟

فرض کن کاربر نوشته:

«چند روز طول می‌کشه سفارش برسه؟»

اگر فقط Semantic Search استفاده کنیم ممکن است متن‌هایی با مفهوم مشابه ولی بدون عدد دقیق برگردد.
اگر فقط Keyword Search استفاده کنیم ممکن است مفهوم کلی از دست برود.

ترکیب این دو باعث می‌شود هم مفهوم و هم اطلاعات دقیق بازیابی شوند.

---

## ⚙️ پیاده‌سازی ساده Hybrid Search

```python id="ragh1"
def hybrid_search(query, vector_results, keyword_results):

    combined = vector_results + keyword_results

    unique = list(set(combined))

    return unique
```

در نسخه واقعی، این ترکیب با وزن‌دهی انجام می‌شود، نه فقط ادغام ساده.

## 🧠 مرحله ۲: Chunking پیشرفته اسناد

یکی از مهم‌ترین بخش‌های RAG حرفه‌ای، نحوه تقسیم متن است.

اگر chunkها خیلی کوچک باشند، اطلاعات ناقص می‌شود.
اگر خیلی بزرگ باشند، مدل دچار نویز و اضافه‌بار می‌شود.

در RAG پیشرفته از روش‌های زیر استفاده می‌شود:

* Chunking بر اساس معنا (Semantic Chunking)
* Chunking با overlap هوشمند
* ساختاردهی بر اساس تیترها و بخش‌ها

📷 [تصویر اینجا قرار گیرد: سند بزرگ → تقسیم به chunkهای معنایی با overlap]

## 🧠 مرحله ۳: Reranking (رتبه‌بندی مجدد نتایج)

در این مرحله، نتایج اولیه‌ای که از Vector DB آمده‌اند دوباره بررسی می‌شوند.

یک مدل سبک‌تر یا حتی یک مدل BERT-based بررسی می‌کند که کدام chunk واقعاً بهترین پاسخ را دارد.

هدف:
👉 بهترین context ممکن برای LLM انتخاب شود، نه فقط نزدیک‌ترین بردار

---

## 🔢 ایده ساده Reranking

فرض کنیم ۳ نتیجه داریم:

* A: مرتبط ولی ناقص
* B: کمی مرتبط
* C: بسیار دقیق

مدل reranker به هرکدام یک امتیاز می‌دهد:

[
score = f(query, document)
]

و بهترین‌ها انتخاب می‌شوند.

## 🧠 مرحله ۴: Context Compression (فشرده‌سازی زمینه)

حتی اگر بهترین chunkها را پیدا کنیم، ممکن است متن خیلی طولانی باشد.

در این حالت از Context Compression استفاده می‌کنیم:

* حذف جملات غیرضروری
* خلاصه‌سازی قبل از ارسال به LLM
* استخراج نکات کلیدی

## ⚙️ مرحله ۵: Multi-Query RAG

در این روش، به جای یک query، چند نسخه از سؤال ساخته می‌شود.

مثلاً:

سؤال کاربر:
«ارسال سفارش چقدر طول می‌کشه؟»

تبدیل می‌شود به:

* زمان ارسال کالا
* مدت تحویل سفارش
* shipping time policy

سپس برای هرکدام retrieval انجام می‌شود.

این کار باعث افزایش دقت می‌شود.

## 🧠 مرحله ۶: حافظه مکالمه (Conversation Memory)

در RAG ساده، هر سؤال مستقل است.
اما در سیستم واقعی، مکالمه ادامه دارد.

مثلاً:

کاربر: سفارش چقدر طول می‌کشه؟

کاربر: اگر تهران باشم چی؟

برای پاسخ درست، مدل باید مکالمه قبلی را بداند.

## 💻 اسکلت ساده RAG پیشرفته

```python id="rag_adv1"
def advanced_rag(query):

    queries = expand_query(query)

    results = []

    for q in queries:

        results += hybrid_search(q, [], [])

    ranked = rerank(query, results)

    context = compress(ranked)

    answer = llm_generate(query, context)

    return answer
```

## ❓ سؤالات تستی

### سؤال ۱

هدف Hybrid Search چیست؟

الف) حذف Embedding
ب) ترکیب جستجوی معنایی و کلمه‌ای
ج) حذف LLM
د) کاهش داده

### سؤال ۲

Reranking در RAG چه کاری انجام می‌دهد؟

الف) حذف داده‌ها
ب) انتخاب بهترین context از نتایج اولیه
ج) آموزش مدل از صفر
د) افزایش اندازه دیتاست

## ✅ پاسخ‌ها

**پاسخ سؤال ۱: گزینه ب**
Hybrid Search ترکیبی از جستجوی معنایی و کلیدواژه‌ای است.

**پاسخ سؤال ۲: گزینه ب**
Reranking بهترین اطلاعات بازیابی‌شده را انتخاب می‌کند.
